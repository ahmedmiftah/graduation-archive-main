نظرة عامة على المنصة

توسيع النظام من "أرشفة مشاريع" إلى منصة متكاملة لإدارة دورة حياة مشروع التخرج بأكملها.

خمسة أنظمة مترابطة بُنيت عبر ثماني مراحل تنفيذ متتالية: استيراد كشف الطلاب وإنشاء حساباتهم، بوابة طالب كاملة، بوابة مشرف، نظام إشعارات مركزي، ونظام نشر/طلب أفكار مشاريع بدورة حياة حجز كاملة، مع كشف تشابه ذكي بالنسبة المئوية يغلق الحلقة. كل مرحلة بُنيت بعد بحث في الكود الموجود أولًا لإعادة استخدامه، لا استبداله — لا حذف ولا كسر لأي وظيفة كانت تعمل من قبل.

Phase 1 — استيراد كشف الطلاب وإنشاء حساباتهم

أول توسيع لنموذج الهوية — النظام لم يكن يعرف مفهوم "حساب طالب" إطلاقًا قبل هذه المرحلة.

✓ 2026-08-15
قاعدة البيانات
جدول students مستقل تمامًا عن project_students الأرشيفي القديم (لم يُمسّ). + imported_student_batches وimported_student_rows لسجل تدقيق كل استيراد صفًا بصف.
آلية الدخول
اسم الدخول = رقم القيد مباشرة. آليًا: بريد داخلي تركيبي {رقم_القيد}@students.local يُخزَّن في users.email، وLoginRequest يحوّل أي مدخل بلا @ لهذا البريد قبل المصادقة. كلمة المرور المؤقتة = تاريخ الميلاد (DDMMYYYY) + إجبار تغييرها عند أول دخول.
الواجهة
معالج استيراد Excel بنمط معاينة ثم تأكيد — التحقق من طول رقم القيد (إعداد نظام قابل للتعديل)، 12 رقمًا للرقم الوطني، عدم التكرار، اكتشاف الطلاب الموجودين مسبقًا. شاشة "الطلاب المستوردون" لإدارة الحسابات لاحقًا (تفعيل/تعطيل، إعادة تعيين كلمة مرور).

Phase 2 — بوابة الطالب

أول واجهة يستخدمها الطالب فعليًا — لوحة تحكم، تقديم مقترح، ومتابعة دورة الحياة.

✓ 2026-08-16
صفحة عامة قابلة للإعلان
/student — بلا تسجيل دخول، تُعيد استخدام مكوّن Browse.vue نفسه (props اختيارية: routeName/loginLabel) بدل تكرار الصفحة، مع زر "دخول طالب" بارز. صفحة /browse الأصلية لم تُمسّ إطلاقًا.
دورة حياة 17 مرحلة — بلا جدول تتبّع

ربط الفريق التلقائي
EnsuresStudentTeamMembership يُدرِج الطالب المسجَّل دخوله تلقائيًا في فريقه قبل التحقق من الطلب. كل زميل يُذكَر برقم قيد مطابق لسجل Student حقيقي يُربط تلقائيًا — رؤية جماعية مشتركة لنفس المقترح.

Phase 3 — بوابة المشرف

أول حساب دخول حقيقي لعضو هيئة تدريس — اختياري، لا يؤثر على أي عضو بلا حساب.

✓ 2026-08-16
تفعيل الحساب
زر "إنشاء حساب دخول" في شاشة أعضاء هيئة التدريس الموجودة — اسم الدخول = البريد الحقيقي المسجَّل أصلًا، كلمة المرور المؤقتة = رقم الجوال المسجَّل (بلا أي حقل جديد في الجدول).
قدرة ضيّقة، لا اعتماد
المشرف يكتب supervisor_note الخاصة به فقط (ability مخصَّصة updateNote) — الاعتماد/الرفض/طلب التعديل يبقى حصرًا لـdept_manager. هذا قرار عدَّل قرارًا سابقًا من Phase 2 (كان القسم يملأ الملاحظة نيابة عن المشرف).

Phase 4 — نظام الإشعارات

تحويل الجرس من رابط ثابت مقصور على دورين إلى مركز إشعارات حقيقي لكل الأدوار الخمسة.

✓ 2026-08-16
4 أحداث حقيقية فقط (من أصل 17 في المواصفة الأصلية)
تقديم/إعادة تقديم مقترح ← مدير القسم · تغيّر حالة المقترح ← الفريق كاملًا + المشرف · تكليف ممتحن ← عضو هيئة التدريس · جاهزية للمناقشة ← المشرف. بقية الأحداث (جدولة مناقشة، اعتماد توثيقات، إخلاء طرف) تفتقر لآلية تفعيل حقيقية بعد.
غلاف موحَّد
كل إشعار — قديم أو جديد — يحمل نفس ثلاثة مفاتيح: title / message / url (رابط يتغيّر حسب دور المستلم). جدول notifications القياسي في Laravel — بلا جدول جديد.

Phase 5 — نظام أفكار المشاريع

أول قدرة نشر حقيقية للمشرف — بدل الاقتصار على المراجعة والموافقة فقط.

✓ 2026-08-17
المشرف ينشئ فكرة مشروع مستقلة (عنوان، وصف، تخصص، مهارات، عدد طلاب مطلوب، كلمات مفتاحية) — تبدأ بحالة متاحة تلقائيًا. الطالب يتصفّح الأفكار المتاحة فقط، مع صفحة تفاصيل لكل فكرة.
قرار نطاق محسوم
لا ربط فعلي بعد بين الفكرة وأي مقترح/مشروع حقيقي — ذلك تحديدًا موضوع Phase 6. لا حذف ناعم (لا جدول يعتمد على project_ideas بعد)، ولا صفحة رقابة إدارية.

Phase 6 — طلبات الانضمام

الجسر بين تصفّح الفكرة والالتحاق الفعلي بها.

✓ 2026-08-17
الطالب يرسل طلب انضمام برسالة اختيارية ← المشرف يقبل أو يرفض من صفحة مراجعة الطلبات. حالة الفكرة تتحدَّث تلقائيًا (محجوزة عند أول قبول، مغلقة عند اكتمال العدد المطلوب).
قاعدة الالتزام الواحد
لا يُسمح بطلب انضمام لصاحب مشروع نشط بالفعل، أو صاحب حجز نشط في مكان آخر — امتداد مباشر لقاعدة "مشروع واحد نشط" الموجودة من Phase 2.
قرار حدود محسوم مع Phase 7
القبول لا ينشئ ProjectProposal فعليًا — ذلك التحويل الكامل يبقى مسؤولية Phase 7 تحديدًا، كما تنص الخطة الأصلية حرفيًا.

Phase 8 — كشف التشابه

المرحلة الأخيرة — من تطابق نصّي بدائي إلى نسبة تشابه % حقيقية.

✓ 2026-08-17
SearchService::detectSimilarity() أصبحت تقارن العنوان (70%) + الوصف (30%) عبر مؤشر Jaccard (تقاطع/اتحاد الكلمات، Unicode-aware يدعم العربية)، ضد المشاريع والمقترحات معًا — بلا مكتبة خارجية.
رُبطت لأول مرة بمساري المقترحات
الموظف والطالب — لم يكونا يستخدمانها إطلاقًا من قبل. رابط كل نتيجة يُبنى حسب صلاحية العارض الفعلية (لا رابط لمقترح فريق آخر لا يملك الطالب صلاحية رؤيته).
عطل عرض مُكتشَف وأُصلح
تحذير المشروع كان يُخزَّن دائمًا لكن لا يظهر أبدًا (يذهب المستخدم لصفحة العرض، والمكوّن كان في صفحة القائمة فقط). أُصلح بإضافة العرض لصفحات العرض الثلاث.

01

تسجيل الدخول

  1. افتح صفحة الدخول
    مباشرة، أو عبر بوابة الطالب العامة القابلة للمشاركة خارجيًا ثم زر "دخول طالب".
    /student → /login
  2. اكتب رقم القيد ككلمة الدخول
    النظام يتعرّف تلقائيًا أن المدخل رقم قيد لا بريد.
  3. كلمة المرور المؤقتة = تاريخ الميلاد (DDMMYYYY)
  4. تغيير كلمة المرور إجباري عند أول دخول
ℹ️ إن لم يُنشئ القسم حساب الطالب بعد، لن ينجح الدخول — التواصل مع القسم مطلوب أولًا.
02

تقديم مقترح مشروع التخرج

  1. من لوحة التحكم، اضغط "تقديم مقترح جديد"
    /student/dashboard → /student/proposal/create
  2. املأ العنوان والوصف والتخصص والمشرف المطلوب
  3. أضف زملاء الفريق (اختياري) بالاسم ورقم القيد
    رقم قيد مطابق لطالب حقيقي يُربط تلقائيًا فيرى نفس المقترح من حسابه.
  4. احفظ — وانتبه لتحذير التشابه إن ظهر
    نسبة % مقابل مشاريع/مقترحات موجودة — تحذير فقط، لا يمنع الحفظ.
  5. تابع الحالة عبر Timeline دورة الحياة
    /student/proposal/{id}
مبدئيمقبول بشرط التعديلمعتمد
03

تصفّح الأفكار وطلب الانضمام

  1. تصفّح الأفكار المتاحة، بفلترة حسب التخصص
    /student/ideas
  2. افتح تفاصيل فكرة لقراءة الوصف والمهارات المطلوبة
    /student/ideas/{id}
  3. أرسل طلب انضمام برسالة مختصرة (اختيارية)
    يظهر فقط إن لم يكن لديك مشروع أو حجز نشط بالفعل.
  4. تابع حالة كل طلباتك في مكان واحد
    /student/idea-requests
04

إدارة الحجز بعد القبول

  1. افتح "حجزي" لرؤية حالته الحالية
    /student/reservation
  2. اضغط "بدء العمل على المقترح" عندما تكون جاهزًا فعليًا
  3. أو "التخلي عن الحجز" إن غيّرت رأيك
    متاح فقط قبل اعتماد المشرف — يحرّرك فورًا لطلب فكرة أخرى.
